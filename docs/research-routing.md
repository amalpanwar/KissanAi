# Document retrieval and Sarvam Hindi answers

The default agentic answer path does not render predefined Hindi crop-guide templates. Cultivation questions and crop follow-ups use the same document pipeline as other agronomic questions. Structured weather, market-price, and profitability tools remain separate. The explicitly disabled agentic mode retains its legacy behavior.

1. Keep the submitted/display question separate from the backend query. Sarvam query translation prepares English for English documents; language-specific variants remain available for Hindi documents.
2. Expand the English query using the shared commodity alias JSON. For example, the Bajra entry includes pearl millet and Cumbu; both the translated question and the original question are matched, so a generic translation does not erase a recognized crop name. Alias expansion changes search terms, not the visible farmer question or crop advice.
3. First resolve the original crop against the shared alias JSON and the production PDF contents. If exactly one guide section matches, select its printed-page boundaries directly, without relying on vector-index recall or an English translation retaining the crop name. Specific questions rerank only that section; broad cultivation questions retain full-section coverage after reranking. No predefined crop advice is used. Unmatched or ambiguous crops continue to general retrieval. Otherwise retrieve semantic candidates from the saved index and supplemental PDFs. The cross-encoder reranks candidates, removes duplicate/reference-list passages, and keeps up to three passages by relative score. Raw logits are ranking scores, not calibrated relevance probabilities; there is no zero-logit cutoff. Alias-expansion annotations are excluded from the ranking question while crop context is retained for follow-ups. Model errors or invalid scores still stop ranking. Empty results or explicit insufficient document evidence trigger official web lookup with the same reranker.
4. Require synthesis to check the crop/topic and return `INSUFFICIENT_EVIDENCE` without advice if no supplied evidence directly answers the question; this does not trigger a corrective generation retry. This model judgment is not a guarantee of relevance. Send only the question and selected evidence to Sarvam chat to synthesize an English answer, with source/page metadata and citation IDs. Reject invalid citations or numeric quantities absent from the evidence. No local answer-generation model is loaded. These checks do not establish complete semantic faithfulness.
5. Pass the generated answer through Sarvam's final Hindi translation. Preserve source references and retrieval records. Keep quantities, formulas, and explicit names protected; if Sarvam alters placeholder tokens, retry surrounding prose without sending the protected values. Invalid output remains rejected. Failed final translation produces an explicit Hindi failure message, not an English source dump.

Deployment requires a compatible saved index/embedding model, cross-encoder, and SARVAM_API_KEY with both chat and translation access. The embedding and reranking models still run locally and need deployment memory; remote answer generation removes the separate local language-model load, but does not prove that all resource problems are resolved. Chat requests have a 25-second timeout. Missing models, documents, provider access, or invalid output are reported as unavailable rather than replaced with crop-specific advice.

Provider calls are mocked in regression tests. These tests verify routing, alias expansion, selected evidence, citation/quantity validation, and final Hindi translation; they do not verify live API credentials or deployed agronomic answer quality.


Final Hindi validation distinguishes residual Latin prose from unsupported numbers. Supported English written-number forms (for example two, half, and twenty-five) may become equivalent numeric digits only in source order and with no duplicated quantities. Digit-valued quantities, formulas, and explicit names retain the existing placeholder protection. If the primary translator leaves Latin prose, retry original unprotected prose with Sarvam Mayura using fully-native Hindi script, leaving protected values local. Native retries use chunks below 1,000 characters, at most four workers and twelve prose chunks per fragment, within the existing fragment/answer time budgets. Invalid retry output remains rejected; retry_model is reported when recovery succeeds. These checks do not establish complete semantic equivalence or support every written-number grammar. The activity footer reports candidate passages separately from reranked evidence used.

## Synthesis validation and recovery

Sarvam English synthesis gets at most two attempts against the same selected evidence (three passages for focused/general search; full resolved section for cultivation overviews). Missing or invalid evidence citations, unsupported numeric quantities, and incomplete generation receive one corrective request with a fixed reason code. The invalid answer is discarded. The second answer must pass the same validation; authentication, transport, and other provider failures do not trigger this retry. General generation requests retain the 25-second HTTP timeout; full-guide overview requests allow 45 seconds. Guide sections above 160,000 source characters are explicitly rejected instead of silently truncated.

Generation diagnostics include attempt count and safe validation reason codes (`missing_evidence_citations`, `invalid_evidence_citations`, `unsupported_quantities`, or `incomplete_generation`). Rejected provider text is not exposed. Reranked passages and source references remain available even when synthesis fails, so the UI count no longer incorrectly resets to zero. Hindi translation runs only after successful English synthesis. Numeric validation is lexical and does not establish factual correctness.

## Deterministic production-guide source selection

The `production_guide_evidence` module derives section names and printed-page boundaries from the deployed PDF contents. It maps commodity aliases to those names, including alternate names in headings. Original explicit crops take precedence over translated names and conversation context. Multi-crop ambiguity returns to general retrieval. No crop-specific page map, advice template, or model-generated alias is used. Crop context is used only when the question names no recognized crop.

Reranking still runs. For broad cultivation questions, all nonbibliographic section chunks supplement the top-ranked passages so the English prompt can cover the full crop cycle; focused questions keep the top three. The prompt asks for a concise source-grounded English guide with regional limitations. References retain PDF page numbers. Full-section prompts can be larger and slower, and source inclusion does not guarantee that a model will cover every stage correctly.

Version `sarvam-hindi-v7` uses the existing Sarvam translation endpoint first. When recovery would need more than four separate protected-prose requests, one Sarvam chat request translates the masked English fragment into Hindi instead. Quantities remain local behind placeholders; order, numeric and Hindi checks still apply. This reduces request fan-out and removes the previous twelve-fragment failure for quantity-rich guides. Sarvam availability and validation can still prevent an answer; source resolution is deterministic, provider output is not.

## References for single-source cultivation overviews

When all selected overview records belong to one resolved guide section in one PDF, the app supplies the reference and section/page scope. Missing model-written inline citation markers do not invalidate that English answer or block Hindi translation. Empty answers, explicit insufficient evidence, invalid supplied citation IDs, and unsupported numeric quantities still fail validation. Focused and multiple-source answers still require inline evidence IDs. Generation diagnostics identify `reference_mode: app_attached_pdf_section`.

Final answer language policy is Hindi sentence prose with recognized technical names optionally retained in English (`sarvam-hindi-v9`). Name recognition uses a separate glossary, repository pesticide-name data, explicit metadata and source-attested variety identifiers; generic English sentences are not whitelisted. See `docs/hindi-translation.md` for the policy and limitations.

## Repeated guide answers

The advisor now checks a source-versioned bilingual guide cache before query translation, retrieval or generation. Successful entries reuse Hindi plus the English answer and PDF page evidence. Failed Hindi output is not cached; valid English can be reused for translation-only retries. Dynamic specialist routes remain uncached. See `docs/guide-response-cache.md` for scope, invalidation, configuration, clearing and Streamlit Cloud persistence limits.
