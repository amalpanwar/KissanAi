# Document retrieval and Sarvam Hindi answers

The default agentic answer path does not render predefined Hindi crop-guide templates. Cultivation questions and crop follow-ups use the same document pipeline as other agronomic questions. Structured weather, market-price, and profitability tools remain separate. The explicitly disabled agentic mode retains its legacy behavior.

1. Keep the submitted/display question separate from the backend query. Sarvam query translation prepares English for English documents; language-specific variants remain available for Hindi documents.
2. Expand the English query using the shared commodity alias JSON. For example, the Bajra entry includes pearl millet and Cumbu; both the translated question and the original question are matched, so a generic translation does not erase a recognized crop name. Alias expansion changes search terms, not the visible farmer question or crop advice.
3. Retrieve semantic candidates from the saved index and supplemental PDFs. The cross-encoder reranks candidates, rejects duplicate/reference-list passages, and keeps up to three accepted passages. If none qualify, check official web evidence with the same verifier.
4. Send only the question and selected evidence to Sarvam chat to synthesize an English answer, with source/page metadata and citation IDs. Reject invalid citations or numeric quantities absent from the evidence. No local answer-generation model is loaded. These checks do not establish complete semantic faithfulness.
5. Pass the generated answer through Sarvam's final Hindi translation. Preserve source references and retrieval records. Keep quantities, formulas, and explicit names protected; if Sarvam alters placeholder tokens, retry surrounding prose without sending the protected values. Invalid output remains rejected. Failed final translation produces an explicit Hindi failure message, not an English source dump.

Deployment requires a compatible saved index/embedding model, cross-encoder, and SARVAM_API_KEY with both chat and translation access. The embedding and reranking models still run locally and need deployment memory; remote answer generation removes the separate local language-model load, but does not prove that all resource problems are resolved. Chat requests have a 25-second timeout. Missing models, documents, provider access, or invalid output are reported as unavailable rather than replaced with crop-specific advice.

Provider calls are mocked in regression tests. These tests verify routing, alias expansion, selected evidence, citation/quantity validation, and final Hindi translation; they do not verify live API credentials or deployed agronomic answer quality.


Final Hindi validation distinguishes residual Latin prose from unsupported numbers. Supported English written-number forms (for example two, half, and twenty-five) may become equivalent numeric digits only in source order and with no duplicated quantities. Digit-valued quantities, formulas, and explicit names retain the existing placeholder protection. If the primary translator leaves Latin prose, retry original unprotected prose with Sarvam Mayura using fully-native Hindi script, leaving protected values local. Native retries use chunks below 1,000 characters, at most four workers and twelve prose chunks per fragment, within the existing fragment/answer time budgets. Invalid retry output remains rejected; retry_model is reported when recovery succeeds. These checks do not establish complete semantic equivalence or support every written-number grammar. The activity footer reports candidate passages separately from reranked evidence used.
