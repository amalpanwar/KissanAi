# Drafts, relevant evidence, and Agmarknet recovery

The composer uses a Streamlit fragment. Draft translation only reruns that fragment; only a `kind: submit` event can hand a question to the app. Browser session storage preserves unfinished text and preview edits across iframe remounts, scoped to the Streamlit session and location epoch. Explicit submission clears the draft. Changing location starts a new composer. Keys stay on the server.

Autocomplete builds Hindi crop labels from the existing commodity alias dictionary. An incomplete phrase such as `rice ki` offers price, varieties, cultivation, and crop protection questions immediately, without a translation API request. Choosing an option fills the box; it does not submit. Sarvam still translates free-form drafts after a pause. Unrecognized crop names retain generic suggestions and the translation preview.

Document embeddings select a broader candidate set. PDFs under `data/raw` that are absent from the saved metadata are discovered automatically, including the Crop Production guide. Page text is cached; a per-language TF-IDF shortlist selects up to 40 passages per source, and the semantic cross-encoder verifies those candidates. This hybrid search can still miss paraphrases with no lexical overlap in unindexed PDFs; rebuilding the primary index remains preferable for complete semantic coverage. A local multilingual cross-encoder (`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`) checks query/passage relevance before any excerpt is shown. Duplicate excerpts and bibliography-like chunks are excluded. Only nonnegative relevance logits pass. This is a conservative relevance filter, not proof of agronomic truth or suitability. Rejected documents trigger official web search and the same verification. Model failure returns no unverified excerpts. Its weights download once and require additional memory; live deployment resource use still needs monitoring.

Agmarknet retries one full dashboard/report cycle after a failed cycle, with a bounded workflow timeout. It retains complete-fetch and freshness checks. Diagnostics are printed and uploaded even on failure; the commodity catalog is committed with CSV and SQLite. Persistent upstream failures still fail the workflow instead of publishing incomplete data.

Validation includes browser pause/resume, Hindi suggestions, explicit send, rerun deduplication, mobile layout, location reset; unit tests for evidence rejection and refresh recovery. Provider calls are mocked in browser tests. A separate manual relevance smoke script exercises real models and the repository corpus.
