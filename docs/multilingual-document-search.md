# Hindi interface with multilingual document retrieval

The Hindi composer preview remains editable. After submission the backend prepares a Hindi version of the accepted question and, only when the indexed corpus contains English text, an English version using the same Sarvam key. Hindi-only document collections skip the English translation. English documents are searched with the English query and Hindi documents with the Hindi query. A chunk's script balance identifies its language; mixed-language and numeric-table chunks remain a limitation of that heuristic.

Research uses the existing configured multilingual embedding model and saved vector index. It no longer uses the hand-written crop/soil synonym list or 75% word-overlap gate. Query vectors score each language partition against the indexed document vectors. Conversation crop context is included; an explicitly named crop takes precedence. The saved vectors must correspond to the configured embedding model and metadata. Missing/misaligned indexes, failed translations, and unavailable encoders are reported separately from no matching evidence in agent activity.

The strongest source excerpts are returned with citations, then the existing Sarvam answer translator renders English prose in Hindi. No cultivar names, prices, or recommendations are generated from a hardcoded answer list. Similarity establishes a candidate match, not proof of an answer or local suitability. `KISAANAI_SEMANTIC_MIN_SCORE` controls the minimum cosine score (default 0.80), and `KISAANAI_SEMANTIC_SCORE_WINDOW` keeps matches within 0.04 of the best score. Passages retain source context. The system does not claim a locally best variety from a general document.

Documents are searched first; when none qualify, the web agent searches official sources and applies the same encoder. Prices remain dated market-data results, not historical numbers taken from crop guides. Full cultivation guides and structured profitability calculations keep their existing document/data paths. Source citations and query-language/search diagnostics remain below the response.

Required deployment assets: `data/processed/chunk_metadata.csv`, its matching vector index, the configured multilingual embedding model, and `SARVAM_API_KEY`. Uploading a PDF alone does not update the vector index: run the existing ingestion/index build before deploying new documents. The index must be rebuilt when changing the embedding model. Answer-translation failure preserves source text with the existing visible translation warning.

Tests cover language-specific query selection, Hindi-only corpora, translation and index failures, follow-up crop context, rejecting low-score unrelated passages, and the Hindi → English price tool → Hindi-output handoff. Provider responses and vector scores are controlled in unit tests; they do not prove quality for every paraphrase or the deployed corpus.

A small real-model smoke check used `intfloat/multilingual-e5-small` with English/Hindi rice and soil-testing queries against four sample passages. It exposed unrelated matches under the earlier 0.72 cutoff; the revised cutoff and relative window rejected those passages. This small sample is not a benchmark of the deployed corpus; tune with reviewed query/source pairs, not user-answer acceptance alone.
